# AI 短剧工作流、开源项目与商业产品调研

调研日期：2026-09-12。用途：为 AI Short Drama Lab 选择可试用的生产工作台与技术路线。

本次核查了官方 GitHub、GitHub API、产品官网、官方价格页，并用浏览器实际打开国内平台的购买入口。没有安装运行候选项目、购买套餐或执行生成，因此下文的成熟度是基于公开工程证据的选型判断，不是成片质量实测。

## 结论与优先顺序

现在已经有覆盖“小说/剧本 → 角色资产 → 分镜 → 视频 → 导出”的完整工作台。最值得优先试用的开源候选是 **Toonflow、ArcReel**；更轻量的候选是 **LocalMiniDrama**。希望做本地模型生产线时，优先考虑 **ComfyUI 加视频、语音模型与剪辑工具**，但需要自己整合项目管理与质检。

商业产品中，**万兴剧厂、小云雀、纳米大片流水线**最贴近中文短剧/漫剧；**LTX Studio**适合需要分镜、角色资产和镜头控制的影视创作；**Runway**适合补充视频生成和修改能力。公开功能和样片不足以证明任何工具可以稳定“无人值守批量出精品剧”。

对本仓库的建议：先用同一段 60–90 秒剧本对比 Toonflow、ArcReel，以及万兴剧厂或小云雀。确定素材可用率和返修流程后，再决定是否开发自己的编排层。

## 如何判断“成熟”

本次关注六项证据：可获取的源码或产品入口、版本发布与维护活动、工作流覆盖、失败恢复和局部重做、素材与工程导出、费用与许可透明度。

- **优先试用**：有较完整工程或产品形态，适合进入真实样片测试。
- **条件试用**：功能相关，但许可、集成或使用门槛影响选择。
- **观察/参考**：项目较新、发布记录薄弱，适合借鉴而不是直接作为量产依赖。

Star 只表示关注度，不代表稳定性；最近推送也不等于所有核心功能已测试。默认分支 README 描述的功能可能尚未进入最新版安装包。

### Toonflow：先验证成片流程

README 提供较具体的官方样片记录：约 2 小时制作、成片约 2 分钟、原始视频约 3 分钟，作者报告语言模型约 ¥10、视频约 ¥120、图像不足 ¥1，总计约 ¥130。这是**作者披露的一次样例**，不包含可确认的人工全成本，也不能推广成“每分钟固定 ¥65”。相较只有宣传词的项目，这类记录更有利于复现验证。[官方说明](https://github.com/HBAI-Ltd/Toonflow-app)

### ArcReel：关注重试、版本和导出

官方页面描述了按阶段编排、失败任务单独重试、生成历史回滚、费用追踪、FFmpeg 成片和剪映草稿导出。这些功能与反复返修的真实短剧制作相关。默认通过云 API 推理，本地不要求 GPU；这也意味着发给模型的文本和参考素材会离开本机。官网仍显示 v0.27.0，而本次 GitHub 最新 Release 为 v0.30.0，部署时应以所选版本文档为准。[官网](https://arc-reel.com/zh/) · [发布记录](https://github.com/ArcReel/ArcReel/releases)

### 三个容易混淆的概念

1. 免费软件与免费生成：调用视频 API 仍会收费；本地模型仍消耗硬件、时间和电力。
2. 本地存储与离线推理：本地工作台接云 API，输入仍可能被发送到模型或素材托管服务。
3. 源码公开与宽松开源：MIT、Apache、GPL/AGPL、Elastic、非商业 CC 许可不是同一种授权。代码许可和上游模型/声音/素材许可也应分别确认。

## 可复用的实际制作工作流

以下是根据上述工具能力整理的建议工作流，不是已经在本仓库跑通的流水线。

```text
故事/小说
  → 分集目标、冲突、对白、结尾钩子
  → 角色/服装/场景/道具资产库
  → 镜头表：时长、景别、站位、动作、对白、参考素材
  → 分镜静帧与临时配音
  → 粗剪预演，确认节奏与对白长度
  → 分镜生成视频，保留版本与成本
  → 人工挑片，局部重做，必要时处理口型
  → 剪辑、字幕、音效、音乐、画面统一
  → 导出可用成片与工程，记录单位成本
```

最有价值的三个检查点：剧本确认后再做资产；分镜图确认后再生成大量视频；对白时长确认后再做口型或表演镜头。角色参考图只降低漂移概率，不能保证复杂遮挡、双人互动、服装和道具跨镜头都正确。

| 路线 | 推荐组合 | 获得什么 | 主要成本 |
| --- | --- | --- | --- |
| 快速验证能否做出剧 | 小云雀/万兴剧厂 → 剪辑精修 | 产品引导、中文流程、快速出初稿 | 平台积分 + 返修人工 |
| 可控可改、无需本机 GPU | Toonflow 或 ArcReel → 云端图像/视频/TTS → 剪辑 | 自有项目资产、提示词、任务记录与导出 | API + 少量部署维护 + 返修 |
| 本地模型与批量实验 | 剧本编排 → ComfyUI → Wan/LTX 系列 → TTS → FFmpeg/剪辑 | 可固定节点、模型和参数，自主控制推理 | GPU/显存 + 模型维护 + 集成与质检 |

### 软件免费的组件路线

- [ComfyUI](https://github.com/Comfy-Org/ComfyUI)：负责图像和视频节点工作流，支持保存与复用。
- [Wan2.2](https://github.com/Wan-Video/Wan2.2)：可用的视频模型候选，仓库为 Apache-2.0。官方 TI2V-5B 720P 示例在启用卸载等选项时要求至少 24GB 显存；这只针对该配置，不代表所有 Wan 模型都只需要 24GB。
- [LTX-2 系列](https://github.com/Lightricks/LTX-2)：音视频生成与 LoRA 训练候选。仓库包含多个许可文件，选择具体模型版本时应对应检查；不要把 LTX Studio 商业订阅与模型仓库混为一谈。
- [CosyVoice](https://github.com/FunAudioLLM/CosyVoice)：中文及多语种语音生成候选，具体权重与声音使用条件分别核对。TTS 本身不解决画面口型对齐。

本次没有测量本机推理性能。当前在 macOS 上开展实验，优先用“本地工作台 + 云 API”可以先验证创作流程，是否采购/租赁 GPU 应在测得稳定产量后再决定。

## 成本估算：按最终可用分钟计算

建议记录：

```text
模型成本 = 文本 + 图像 + 所有视频生成（含废片）+ 语音 + 口型/放大/修改
全成本 = 模型成本 + 平台固定费用分摊 + 算力/存储 + 人工
每可用分钟成本 = 全成本 / 最终验收成片分钟数
视频生成成本近似 = 成片秒数 × 生成素材倍率 × 对应模型每秒价格
```

“生成素材倍率”同时包含失败、重复尝试和剪掉的部分，不应再把同一批废片重复加价。

仅作敏感性计算：假设做 90 秒成片，需要生成 3 倍素材，即 270 秒；若所选模型价格为 ¥0.3/秒，则视频生成约 ¥81；若为 ¥1.25/秒，则约 ¥337.5。两种单价取自本次万兴体验档不同模型的展示，质量与功能不同；这不是同等质量比价，也不是总成本报价。实际购买的积分包可能高于本次实际消耗。[价格入口](https://www.reelmate.cn/)

免费额度适合学习和比较，不能默认支撑持续量产。对于当前项目，建议把首轮总测试预算设为 **¥300–800 的可选上限**，只选 2–3 条路线、小规模生成；这是实验预算建议，不是已获得的支出授权，也不是供应商报价。

## 给本仓库的首轮验证方案

测试片规格建议：60–90 秒，9:16，两个角色、两个场景、12–18 个镜头、一次服装/道具连续性检查、一段双人对白。所有候选使用相同剧本和角色参考素材，降低题材差异影响。

| 评估项 | 记录方式 |
| --- | --- |
| 故事与节奏 | 是否保留冲突和结尾钩子；人工改写分钟数 |
| 角色、服装、道具一致性 | 各镜头通过/不通过，注明具体错误 |
| 视频可用率 | 被采用的生成素材秒数 / 总生成素材秒数 |
| 对白与口型 | 台词正确、音色一致、口型及情绪是否可接受 |
| 可修改性 | 改一条台词或一个道具需要重做多少上游/下游步骤 |
| 失败恢复 | 中途失败后能否续跑，是否重复扣费 |
| 导出 | MP4、独立素材、提示词/参数、剪辑工程能否保留 |
| 成本 | 模型消耗、订阅分摊、人工工时分别记录 |

建议顺序：

1. **Toonflow**：验证安装、模型配置和完整成片是否顺畅。
2. **ArcReel**：重点验证任务恢复、版本记录、费用与剪映导出。
3. **万兴剧厂或小云雀**：作为现成产品对照，检验节省的人工作业是否值得平台费用。

首轮结束后再选择架构。如果瓶颈是画面和对白返修，就改善镜头生产；如果瓶颈是批量任务和素材追踪，就补编排。当前仓库尚未接入模型，没有必要在获得这些数据前重写一个全栈短剧平台。

## 核验边界与待确认项

- 未执行候选项目代码，未完整观看和逐镜评审样片；作者效率、产量与一致性宣传不能当作本次测试结论。
- 小云雀赠送积分数量、套餐价格；纳米的免费额度与正式价格，未核实。
- 各工具真实中文对话效果、跨集稳定性、剪映当前版本兼容性、API 并发与失败退款，需要在样片测试中确认。
- 授权信息按当日项目与产品说明记录，不把生成内容商用、代码再分发、改造成 SaaS 视作同一件事。
- 仅检索普通调研范围，未穷尽所有仓库、产品及模型。观察候选可以持续变化，但本次优先顺序已足够支撑一次实际选型实验。
