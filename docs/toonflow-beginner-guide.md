# Toonflow 从零到第一条短片

核验日期：2026-09-12。面向 Mac 新手，目标：完成约 30 秒、单角色、单场景的练习片《最后一杯咖啡》。

依据：官方 Release v1.1.8、对应 README、官方演示截图、前端设置与操作文案。部分菜单名称参考前端当前 master，安装包可能不同。本次没有安装运行或调用收费模型；下面是经资料核对的教程，尚不是本机实测记录。

## 先准备什么

Toonflow 管理创作流程，模型负责实际生成。首次使用需要三类服务：

| 类型 | 用途 | 选择条件 |
| --- | --- | --- |
| 文本模型 | 事件分析、剧本、分镜和提示词 | 与所选供应商适配，支持工具调用；不要仅确认它能普通聊天 |
| 图片模型 | 人物设定、场景、分镜静帧 | 最好支持参考图/图生图，以复用同一人物 |
| 视频模型 | 把静帧变成几秒视频 | 支持单图或首帧驱动，确认可用时长、分辨率、有声/无声能力 |

每类服务通常需要：供应商名称、API 请求地址、API Key、模型 ID。可以由一家供应商提供，也可分开配置。API Key 在本机设置中输入即可，不必发送到聊天里。模型 ID 应从你的供应商控制台原样复制；展示名称不是调用 ID。

首轮只接一套能用的服务。参考图能力、视频时长和音频支持必须与真实模型一致；在界面里勾选能力不会让模型获得该能力。云 API 路线通常无需为本机另配 GPU，生成仍可能收费。

## 第 1 步：安装和登录

打开 [官方 v1.1.8 发布页](https://github.com/HBAI-Ltd/Toonflow-app/releases/tag/v1.1.8)，展开 Assets。

- Mac M 系列：下载 `ToonFlow-1.1.8-mac-arm64.dmg`。
- Intel Mac：下载 `ToonFlow-1.1.8-mac-x64.dmg`。
- 判断方法：苹果菜单 → 关于本机，查看芯片/处理器。

打开 DMG，把 ToonFlow 拖入“应用程序”，再启动。普通用户不需要下载 Source code、安装 Node.js 或部署 Docker。首次遇到 macOS 阻止打开时，官方发布说明提供“系统设置 → 隐私与安全性”的单应用允许打开方法；若提示明确检测到恶意软件，应停下核实，不能仅按未签名应用处理。

官方默认登录：账号 `admin`，密码 `admin123`。这是本地工具登录，与模型供应商账号分开。

**完成标志：** 看到“我的项目”页面及“新建项目”。

## 第 2 步：接通三个模型

进入左下角设置 → **模型服务**。

1. 优先选择已有且与你的服务对应的供应商，不先进入“编辑代码”。
2. 按该供应商要求填写 API Key 和请求地址。Base URL 是否含 `/v1` 由具体适配器决定，不统一追加。
3. 启用供应商；如果没有所需模型，点“手动添加”。
4. 填写显示名称、模型标识和模型类型；依照服务实际能力填写图片/视频模式、时长与分辨率。
5. 保存/完成输入后，确认出现配置已更新的反馈。
6. 使用“测试”，先文本，再图片，最后视频。

模型测试会真正发请求。特别是图片、视频测试可能发生实际扣费，并非只检查连接。

如果测试框允许自定义输入，可用：

```text
文本：把“咖啡师发现门外有一只湿猫”拆成三个简短事件。
图片：一只白色咖啡杯，放在深棕色木桌上，暖色灯光，无文字。
视频：固定镜头，咖啡杯保持不动，只有热气缓缓上升。
```

部分版本使用固定测试输入，此时直接检查返回结果。视频选界面支持的较短时长；一张测试图片只需生成一次。

**完成标志：** 文本返回内容，图片可预览，视频成功生成并能播放。文字模型还要在下一步实际 Agent 任务中验证工具调用能力。

来源：[模型服务 UI](https://github.com/HBAI-Ltd/Toonflow-web/blob/master/src/components/setting/components/vendorConfig.vue) · [模型测试实现](https://github.com/HBAI-Ltd/Toonflow-app/blob/v1.1.8/src/routes/setting/vendorConfig/modelTest.ts)

## 第 3 步：给 Agent 分配模型

在设置 → **Agent配置**，使用“简易配置”。逐个点开当前流程会使用、但仍显示“未配置”的文本任务卡片，选择刚测试通过的文本模型并确认。新手可先共用同一个合适的文本模型，保留默认高级参数。

“模型服务”是登记可用模型，“Agent配置”是指定每项任务用哪个模型。前者成功不代表后者已经配置。图片和视频模型还需要在对应生成面板选择。

如果你的版本出现“模型映射”，它还涉及不同生成模式的提示词绑定。先使用默认匹配；提示缺少模式或映射时，再检查所选图像/视频模型的模式和绑定。

**完成标志：** 所需 Agent 卡片显示模型名称；新建项目后的事件分析能完成。

来源：[Agent 配置界面](https://github.com/HBAI-Ltd/Toonflow-web/blob/master/src/components/setting/components/agentConfog.vue)

## 第 4 步：创建练习项目并导入原文

“我的项目”→“新建项目”，填写：

| 字段 | 练习值 |
| --- | --- |
| 项目名称 | 最后一杯咖啡—练习 |
| 小说类型 | 都市温情 |
| 影片画风 | 从实际列表选择一种写实或插画风，并全程保持 |
| 影片比例 | 9:16 |
| 小说简介 | 打烊前，咖啡师把最后一份温暖留给门外的流浪猫。 |

进入原文区域 →“导入原文”，上传练习 TXT 或直接粘贴。核对解析出的章节，勾选第一章，保存并进行“事件分析”。界面允许保存与分析分开执行时，保存后再选中章节分析。

练习原文位于：`experiments/toonflow-first-film/source.txt`。

**完成标志：** 原文列表存在“第一章 最后一杯咖啡”，能查看打烊、发现猫、端水、留下灯光等事件。不要在原文未保存或事件仍生成时反复启动编剧。

来源：[创建项目字段](https://github.com/HBAI-Ltd/Toonflow-web/blob/master/src/views/project/components/addProject.vue) · [导入原文](https://github.com/HBAI-Ltd/Toonflow-web/blob/master/src/views/novel/components/importNovel.vue)

## 第 5 步：让编剧 Agent 写一集

进入编剧/ScriptAgent 区域，在聊天框发送下面的练习指令（本教程编写，不是官方固定命令）：

```text
请把已导入的《最后一杯咖啡》改编成一集约30秒的竖屏短片。
只保留一个人类角色林夏、一只橘白猫和咖啡店门口这个连续场景。
主角固定为：28岁女性，黑色齐肩直发，米白衬衫，深棕围裙。
叙事靠动作和表情，不要旁白，不增加配角，不改变服装。
先给我故事骨架和改编策略，再生成单集剧本。
目标6个镜头，最终剪辑每镜约5秒；只保留一句对白“明天见”。
先完成文字，不生成图片或视频。
```

检查“故事骨架”“改编策略”“剧本”三个区域是否有内容，剧本管理里是否确实出现一集。聊天说“完成”不能代替已保存的剧本。

如果结果变成多集、增加路人或换装，继续要求局部改写。先确认剧本，再进入制作。

## 第 6 步：固定人物和场景资产

进入制作/ProductionAgent 画布，对应当前这一集。按实际流程生成或关联资产，先确定一份可用的人物参考和一份场景参考。

可发送：

```text
基于当前剧本整理资产和6个分镜。
人物只使用林夏：28岁女性、黑色齐肩直发、米白衬衫、深棕围裙。
场景统一为暖光咖啡店门口，深棕木门、右侧玻璃窗、雨后地面。
猫为橘白短毛猫，道具为白色陶瓷水碗。
先准备资产与分镜文字，并告诉我还缺哪些参考图，暂不批量生成视频。
```

在资产卡片/生成图片面板选择图片模型，逐项生成或上传参考图。确认满意后固定使用，不要每个镜头重造一个人物。检查衣服、发型、门的位置和猫的花色。

**完成标志：** 当前集能引用同一套人物、场景、猫和道具素材。

来源：[官方画布示例](https://github.com/HBAI-Ltd/Toonflow-app/blob/v1.1.8/docs/screenshot/5.png)

## 第 7 步：先分镜图，后视频

建议的六镜顺序（可让 Agent 调整，但保持故事简单）：

| 镜头 | 画面与动作 | 检查重点 |
| --- | --- | --- |
| 1 | 店内看向门口，林夏准备熄灯 | 建立门、窗和灯的位置 |
| 2 | 林夏停下动作，目光投向门外 | 人物脸、服装与上一镜一致 |
| 3 | 门外橘白猫坐在檐下，抬头 | 猫花色，避免额外动物 |
| 4 | 特写：手把白色水碗放在门边 | 只做一个动作，检查手和碗 |
| 5 | 猫低头饮水，林夏在门内微笑 | 检查空间位置；复杂可拆镜 |
| 6 | 林夏轻声说“明天见”，留下门口灯 | 结尾情绪；对白难可用字幕 |

先生成第一镜分镜图，满意后再补其他镜头。在图像模型支持时附上资产参考图。别一次生成多套不同人物。

进入制作工作台的视频生成面板，选择一个镜头/Track：

1. 选视频模型。
2. 新手优先用模型实际支持的“单图”或“首帧”模式，放入已确认的分镜图。
3. 选可用的时长和分辨率。5秒是练习的剪辑目标；模型只支持其他时长时，生成后裁剪。
4. 生成或编辑视频提示词。提示词重点描述动作和镜头运动。
5. 点“生成视频”，等待成功，播放检查，并选择采用的版本。
6. 单镜确认后，再逐个处理其他镜头或小批量生成。

第一镜示例：

```text
保持参考图的人物、服装、咖啡店门窗位置和暖色光线。
固定机位。林夏缓慢抬起右手，准备触碰墙边开关，随后停住。
自然动作，不新增人物，不切换场景，不出现文字。
```

“生成提示词”和“生成视频”是两个操作；只有文字不代表已有视频。有声输出也取决于模型。第一轮可以全片无对白，末镜添加“明天见”字幕，先跑通画面。

若出现 Track，一个 Track 可能组织多个分镜，不一定等于一个镜头；先检查提示词中的镜头数量和总时长，避免误把多镜头视频按单镜预算。

来源：[官方视频生成界面](https://github.com/HBAI-Ltd/Toonflow-app/blob/v1.1.8/docs/screenshot/10.png)

## 第 8 步：拼接、导出和复盘

把采用的视频放入剪辑/时间线区域，按故事顺序排列，裁去动作开始前后多余部分。首轮不要大量叠加转场；正常切镜即可。可在可用编辑界面补音频和字幕，或下载素材到熟悉的剪辑软件处理。

点击“导出视频”并在播放器中从头到尾检查。如果找不到内置导出，先使用生成面板提供的批量下载视频，手动剪辑。不要把“导出项目”、下载素材压缩包或生成提示词当作已导出成片；也不要默认所有版本都支持剪映工程。

最终验收：文件能播放、顺序正确、约30秒、人物不突然换脸/换衣、无重复镜头、音频不串镜、结尾可理解。

记录实际生成次数、模型消耗、人工分钟数。成功生成但没采用的素材也算成本。

来源：[剪辑界面源码](https://github.com/HBAI-Ltd/Toonflow-web/blob/master/src/views/production/components/workbench/editVideo/index.vue)

## 常见卡点

| 现象 | 优先检查 |
| --- | --- |
| 模型测试成功，Agent仍不工作 | Agent是否绑定、供应商/模型是否启用、模型是否支持工具调用 |
| 401/403 | Key、所属供应商、账号权限；按具体错误处理 |
| 404/模型不存在 | Base URL、模型ID、路由或供应商适配器；不要盲目反复加 `/v1` |
| 余额不足/429 | 余额、限流或并发；先看上游任务状态，再决定重试 |
| 图片可以生成，视频失败 | 模型类型、生成模式、必填参考图、支持的分辨率/时长 |
| 同一个人物每镜都不一样 | 是否真正附带参考图，文字与参考是否矛盾，衣服是否锁定 |
| 有分镜但没有画面 | 是否只完成文字；图片任务是否生成成功且关联到当前分镜 |
| 有片段但导出为空 | 是否选用了生成版本，是否放到时间线，是否选对剧集 |
| 一直生成中 | 看供应商任务状态；已成功的任务可能只是结果回传失败，勿连续重发 |
| 教程与界面不同 | 先确认版本号与仓库归属，同名 fork 和旧版教程可能不同 |
